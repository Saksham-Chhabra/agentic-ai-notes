Send the same question to multiple LLMs, collect their answers, then use another LLM (the "judge") to rank them. This is a real-world pattern for improving response quality.

Day 4: System Prompts, Conversation History & Digital Twin

Three Key Concepts
  • System Prompt — Describes the AI's role and context for the conversation.
  • Conversation History — The complete conversation so far, passed as a list of messages.
  • Illusion of Memory — Every LLM call is stateless. We re-send the entire history each time.

System Prompt + Conversation History

messages = [
    {"role": "system", "content": "You are a snarky, witty assistant"},
    {"role": "user",   "content": "Hi, my name is Ed"},
    {"role": "assistant", "content": "Well hi there, Ed."},
    {"role": "user",   "content": "What's my name?"},  # It "remembers" via history
]

Building a Digital Twin Chat

from pypdf import PdfReader
import gradio as gr

reader = PdfReader("twin/linkedin.pdf")
linkedin = ""
for page in reader.pages:
    text = page.extract_text()
    if text:
        linkedin += text

system_prompt = f"""You are a digital twin on a website.
Here are the person's details: {summary}
Here is their LinkedIn: {linkedin}
Be professional and engaging."""

def chat(message, history):
    messages = [{"role": "system", "content": system_prompt}] \
             + history + [{"role": "user", "content": message}]
    response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages)
    return response.choices[0].message.content

gr.ChatInterface(chat).launch(inbrowser=True)

Day 5: Tools & The Agent Loop

What is a Tool?

A tool is a Python function the LLM can request to call. You describe it with a JSON schema. When the model wants to use a tool, it returns finish_reason="tool_calls" instead of text.

Step 1: Define the Function and its JSON Schema

def record_email_tool(email):
    with open("emails.txt", "a") as f:
        f.write(email + "\n")
    return "Email received"

record_email_tool_json = {
    "name": "record_email_tool",
    "description": "Record a user's email address",
    "parameters": {
        "type": "object",
        "properties": {
            "email": {"type": "string", "description": "The email address"}
        },
        "required": ["email"],
        "additionalProperties": False
    }
}

tools = [{"type": "function", "function": record_email_tool_json}]

Step 2: The Agent Loop (while loop)

def chat(message, history):
    messages = [{"role": "system", "content": system_prompt}] + history \
             + [{"role": "user", "content": message}]
    response = openai.chat.completions.create(
        model="gpt-5.4-mini", messages=messages, tools=tools)

    # THE AGENT LOOP
    while response.choices[0].finish_reason == "tool_calls":
        message = response.choices[0].message
        messages.append(message)
        for tool_call in message.tool_calls:
            args = json.loads(tool_call.function.arguments)
            result = record_email_tool(**args)
            messages.append({
                "role": "tool",
                "content": result,
                "tool_call_id": tool_call.id
            })
        response = openai.chat.completions.create(
            model="gpt-5.4-mini", messages=messages, tools=tools)

    return response.choices[0].message.content
The Agent Loop is simply a while loop that keeps making LLM calls as long as the model wants to use tools. When done, it returns text. This is the core mechanic of ALL agentic AI — frameworks just abstract it away.

Dynamic Tool Dispatch with globals()

def handle_tool_calls(tool_calls):
    results = []
    for tool_call in tool_calls:
        tool_name = tool_call.function.name
        arguments = json.loads(tool_call.function.arguments)
        tool = globals().get(tool_name)
        result = tool(**arguments) if tool else "No tool found"
        results.append({"role": "tool", "content": json.dumps(result),
                        "tool_call_id": tool_call.id})
    return results

Extra: Visible Agent Loop with Checklist Tools

Making the Loop Visible

Uses the rich library for formatted terminal output and a checklist pattern: the LLM creates a checklist, works through items, and marks each complete via tool calls.

from rich.console import Console

checklist = []
completed = []

def create_checklist(descriptions: list[str]) -> str:
    checklist.extend(descriptions)
    completed.extend([False] * len(descriptions))
    return get_checklist_report()

def mark_complete(index: int, completion_notes: str) -> str:
    completed[index - 1] = True
    return get_checklist_report()

def loop(messages):
    response = openai.chat.completions.create(
        model="gpt-5.5", messages=messages, tools=tools)
    while response.choices[0].finish_reason == "tool_calls":
        message = response.choices[0].message
        results = handle_tool_calls(message.tool_calls)
        messages.append(message)
        messages.extend(results)
        response = openai.chat.completions.create(
            model="gpt-5.5", messages=messages, tools=tools)
    Console().print(response.choices[0].message.content)

Day 1: Agent, Runner, Tools & Memory

The Three Core Primitives
  • Agent — Wraps an LLM with a name, instructions, model, and optional tools.
  • Runner — Executes the agent loop. Runner.run() loops through tool calls automatically.
  • trace — Wraps a run for observability; visible at platform.openai.com/traces.

Creating and Running an Agent

from agents import Agent, Runner, trace, function_tool

agent = Agent(name="Jokester", instructions="You are a joke teller",

result = await Runner.run(agent, "Tell a joke about AI Agents")
print(result.final_output)

with trace("Telling a joke"):

Day 2: Multi-Agent Orchestration

Two Orchestration Models
  • By Code — Python controls the flow (asyncio.gather, sequential calls). Predictable.
  • By LLM — The LLM decides which agents/tools to use. Two sub-approaches: via Tools (agent.as_tool) and via Handoffs.

Orchestration by Code (Parallel + Picker)

import asyncio

with trace("Sales selection"):
    results = await asyncio.gather(
        Runner.run(sales_agent1, message),
        Runner.run(sales_agent2, message),
        Runner.run(sales_agent3, message),
    )
    outputs = [r.final_output for r in results]
    best = await Runner.run(sales_picker, "\n".join(outputs))

Agents as Tools

# Convert an agent into a tool
tool1 = sales_agent1.as_tool(
    tool_name="writer_1",
    tool_description="Write a sales email"
)

# A manager agent gets sub-agents + function tools
sales_manager = Agent(
    name="Sales Manager",
    instructions="Generate drafts, select, and send the best.",
    tools=[tool1, tool2, tool3, send_email_tool],
    model=MODEL_NAME
)

Handoffs

# Handoffs pass control permanently: A → B (not A → B → A)
sales_manager = Agent(
    name="Sales Manager",
    tools=[tool1, tool2, tool3],
    handoffs=[sales_sender],  # delegates to this agent
    model=MODEL_NAME
)
Tools: A → B → A (control returns). Handoffs: A → B (control passes permanently). Tools-based delegation is generally more predictable.

Structured Outputs with Pydantic

from pydantic import BaseModel, Field

class EmailReview(BaseModel):
    is_professional: bool = Field(description="Whether professional")
    number_of_sentences: int = Field(description="Sentence count")
    contains_placeholders: bool = Field(description="Has placeholders")

checker = Agent(name="Checker", instructions="Review sales emails",
               model="gpt-5.4-mini", output_type=EmailReview)

result = await Runner.run(checker, email_text)
review = result.final_output  # An EmailReview instance!
print(review.is_professional)

Output Guardrails

from agents import output_guardrail, GuardrailFunctionOutput

@output_guardrail
async def email_guardrail(ctx, agent, message):
    result = await Runner.run(checker, message, context=ctx.context)
    review = result.final_output
    is_problem = review.contains_placeholders or not review.is_professional
    return GuardrailFunctionOutput(
        output_info={"review": review},
        tripwire_triggered=is_problem
    )

agent = Agent(..., output_guardrails=[email_guardrail])
Guardrails Gotcha

Input guardrails only run on the first input to the first agent. Output guardrails only run on the final output of the last agent. Guardrails on intermediate agents are never triggered.

Day 1: Understanding & Using MCP Servers

What is MCP?

The Model Context Protocol lets an agent use tools that someone else wrote and runs as a separate program. An MCP server exposes tools; an MCP client discovers and calls them.

Two Types of MCP Servers
  • Local (Stdio) — Spawned as a subprocess. Use MCPServerStdio. Started with uvx or npx.
  • Remote (HTTP) — Hosted services. Use MCPServerStreamableHttp. Nothing to install.

Local MCP Server (Fetch)

from agents.mcp import MCPServerStdio

fetch_params = {"command": "uvx",
                "args": ["--with", "mcp<2", "mcp-server-fetch"]}

async with MCPServerStdio(params=fetch_params,
                          client_session_timeout_seconds=60) as server:
    tools = await server.list_tools()

Playwright MCP Server (Browser Automation)

playwright_params = {"command": "npx",
                     "args": ["@playwright/mcp@latest"]}
# Provides: browser_navigate, browser_click, browser_screenshot...

Filesystem MCP Server (Sandboxed)

sandbox_path = os.path.abspath("sandbox")
files_params = {"command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem",
            sandbox_path]}
# Provides: read_file, write_file, list_directory

Combining Multiple MCP Servers with an Agent

TASK = "Find a recipe, then summarize it to banoffee.md"

async with MCPServerStdio(params=files_params, ...) as mcp_files:
    async with MCPServerStdio(params=playwright_params, ...) as mcp_browser:
        agent = Agent(
            name="investigator",
            instructions="Browse the web and write files.",
            model="gpt-5.4-mini",
            mcp_servers=[mcp_files, mcp_browser]
        )
        with trace("investigate"):
            result = await Runner.run(agent, TASK, max_turns=20)

Remote MCP Server (Context7)

from agents.mcp import MCPServerStreamableHttp

params = {"url": "https://mcp.context7.com/mcp", "timeout": 60}

async with MCPServerStreamableHttp(name="Context7", params=params) as server:
    agent = Agent(name="Expert",
                  instructions="Use Context7 to answer.",
                  mcp_servers=[server], model="gpt-4o-mini")
    result = await Runner.run(agent, question)
Windows Jupyter Fix

On Windows, MCP servers crash in Jupyter because stderr has no file descriptor. Fix:

import functools, subprocess
import agents.mcp.server

agents.mcp.server.stdio_client = functools.partial(
    agents.mcp.server.stdio_client, errlog=subprocess.DEVNULL)
